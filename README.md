# Flask MVP: контроль качества целей сотрудников

Минимальный проект на "обычном" Flask (без админок и расширений), который можно запустить на мок-данных и затем подключить к вашему личному кабинету и классу `giga`.

## Что умеет MVP

- Загружает мок-данные сотрудников (120 записей, офис + производство).
- Считает:
  - `goal_quality_score` — качество постановки цели.
  - `result_quality_score` — качество формулировки результата.
  - `strategic_impact_score` — признак влияния цели на бизнес/развитие.
  - `goal_completion_rate` — доля выполненных целей.
- Строит **HR-сигналы риска**:
  - низкое качество целей при высокой итоговой оценке,
  - высокая оценка/выполнение при низком стратегическом влиянии,
  - слабая дисциплина целеполагания и отчетности.
- Показывает сводку по отделам, включая долю сотрудников с флагами риска.
- Показывает карточку сотрудника с деталями по каждой цели.
- Есть страница **самопроверки** (для HR и сотрудников).

## Назначение

Сервис предназначен для приоритезации ручной проверки HR/руководителями. AI-флаги не должны автоматически приводить к кадровым решениям без верификации фактов.

## Быстрый запуск

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python app.py
```

Откройте: `http://127.0.0.1:5000`

## Структура

- `app.py` — роуты и запуск Flask.
- `data/mock_data.py` — генерация тестовых сотрудников.
- `services/analyzer.py` — эвристики оценки цели/результата/влияния и формирование флагов риска.
- `services/llm_client.py` — адаптер для подключения вашей `giga`-функции.
- `templates/` — HTML-шаблоны.
- `static/styles.css` — базовые стили.

## Как подключить ваш класс LLM

В `app.py` сейчас стоит:

```python
llm_client = LLMClient(enabled=False)
```

Когда будете готовы:

1. Положите ваш модуль (с функцией `giga`) в проект.
2. Импортируйте функцию в `app.py`.
3. Передайте её в адаптер:

```python
from your_module import giga
llm_client = LLMClient(enabled=True, giga_callable=giga)
```

После этого включайте LLM через checkbox `use_llm` в интерфейсе.

## Важно для продакшена

- Не храните токены в коде.
- Добавьте логирование и аудит решений.
- Добавьте ручную валидацию HR (human-in-the-loop).
- Разделите правила для office и production ролей (дальше расширяйте по кластерам должностей).
- Формализуйте процесс апелляций сотрудника по AI-сигналам.
